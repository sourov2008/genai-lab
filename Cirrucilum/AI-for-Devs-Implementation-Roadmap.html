Source syllabus: AI for Devs_6 modules - Vollzeit · joinmsit.de · ℅ Mindspace, Münzstr. 12, 10178 Berlin

Operating rule. Do not treat this as six separate courses. Module 1 is literacy. Modules 2–6 are sequential releases of the same app: schema → CRUD → LLM → UI/deploy → auth/agents → RAG/pitch. Freeze the product domain by Friday of week 4.

1. How to implement the syllabus

Run one private GitHub repo (suggested name: genai-capstone) from week 5 onward. Every taught topic should land as a commit on that product, not as a throwaway notebook—except Module 1 labs, which live in a separate genai-lab repo.

Week 0 setup (before or during week 1): GitHub account, Cursor, Python 3.12, Docker Desktop, OpenAI API key, Gemini API key, Postgres via Docker. Create .cursor/rules for secret handling and “no business logic in routes”. Never commit .env.

Default stack: FastAPI (Flask if the classroom requires it), SQLAlchemy 2, Postgres, Alembic, Pydantic, Jinja2 + Bootstrap, OpenAI + Gemini adapters, Render, pytest, Langfuse (or equivalent tracing), Chroma or pgvector, n8n.

3. Capstone shape

Pick a narrow job-to-be-done with documents and structured records. Example domains: study coach, grant screener, meeting-to-tickets, clinical-admin summarizer (non-diagnostic), internal policy Q&A.

Must exist by week 16 (MVP): users, generation jobs, versioned prompts, structured artifacts in Postgres, HTML UI, deployed URL, Swagger, provider adapter.

Must exist by week 24 (v1): JWT, tests in CI, traces, one tool-using agent, n8n helper, RAG with citations, eval report, pitch deck, public README.

Module 1 — Advanced 3: Introduction to Generative AI

Weeks 1–4 · 200 UE · Theme: foundations before the product

Exit outcome: Explain LLM capabilities and limits, ship quality prompts in Cursor/Copilot, call OpenAI and Gemini from code, and freeze a portfolio product idea.

Stack: Python 3.12, Cursor, OpenAI SDK, Google GenAI SDK, optional Flask.

Gate: Written product one-pager + 3 working API notebook/scripts.

Deliverable: Personal GenAI lab repo + product one-pager used as the spec for Modules 2–6.

Day shape: Morning: concept + short lab. Afternoon: API drills in Cursor. End of day: 5-line learning log and saved prompt snippets.

Week-by-week

WeekThemeTeach / practiceYou ship
W1GenAI + NLP mapTokens, embeddings vs generation, transformer intuition, hallucination, context windows, safety.Glossary + 10-prompt lab in Cursor (system / user / few-shot).
W2LLM product thinkingUse cases that fit LLMs vs classical ML. Cost, latency, eval. Copilot/Cursor workflows for real coding.Rebuild a small CLI using the assistant; document what you still had to verify.
W3Master LLM APIsOpenAI + Gemini: auth, chat completions, temperature, max tokens, JSON mode, streaming, errors, rate limits.Same task on both providers; comparison table of quality, cost, latency.
W4Portfolio planning + optional PythonPick one AI product. Scope MVP vs v2. Fill Python / OOP / Flask / SQLAlchemy gaps if needed.One-pager: problem, user, AI job, non-goals, data, APIs, 4-week MVP slice.

How to implement this module

  • Treat Cursor as the primary IDE from day 1: rules, composer, inline edit, and review of diffs.
  • Never paste secrets: .env + .gitignore; rotate keys if they leak.
  • Optional Python track is not extra credit if you are weak on HTTP, classes, or SQL — do it in weeks 3–4 mornings.
  • Freeze the product domain by Friday of week 4. Changing later burns Module 2.

Optional Python catch-up: functions → OOP → virtualenv → Flask hello world → SQLAlchemy one-to-many. Do not let catch-up delay the product one-pager.

Module 2 — Advanced 4: Introduction to your AI software project

Weeks 5–8 · 200 UE · Theme: ethics, agents, then a real backend

Exit outcome: Frame an ethical AI MVP, sketch agents/observability, design the schema, and ship a FastAPI/Flask service with CRUD.

Stack: FastAPI (preferred) or Flask, SQLAlchemy, Postgres, Alembic, Pydantic, pytest skeleton.

Gate: Running API with migrations + README that a classmate can clone and boot.

Deliverable: MVP backend v0: Docker Compose, migrations, CRUD, ethics notes. No LLM in the production path yet.

Day shape: Morning: design or ethics reading. Afternoon: implement one vertical slice (model → schema → route → test).

Week-by-week

WeekThemeTeach / practiceYou ship

W6MVP phase 1 — idea and schemaUser stories, acceptance criteria, entity-relationship diagram, API resource list.ERD + OpenAPI stub for 3–5 core resources (User, Session/Job, PromptRun, Artifact).

How to implement this module

  • Prefer FastAPI + Pydantic for typed contracts; Flask is allowed if that is the class default.
  • Model PromptRun early even if generation comes next module — you will persist prompts, raw output, and structured JSON.
  • Keep agents conceptual this month: one sequence diagram of a future agent, not LangGraph in production.
  • Observability stub: request_id + structured logs. Full tracing waits until Module 5.

Module 3 — Advanced 5: Prompting and API integration

Weeks 9–12 · 200 UE · Theme: LLM in the request path

Exit outcome: Connect the DB to a live generation endpoint, iterate prompts, and persist structured outputs.

Stack: Provider SDKs, JSON schema / structured output, optional background jobs, prompt version table.

Gate: POST /generate creates a DB row with prompt version, raw text, parsed JSON, and model metadata.

Deliverable: Generation feature with versioned prompts and persisted structured artifacts.

Day shape: Morning: prompt experiments in a notebook or playground, then port winners into code. Afternoon: productionize the winner.

Week-by-week

WeekThemeTeach / practiceYou ship
W9MVP phase 2 — wire CRUD to DBHarden endpoints, pagination, filters. Fix N+1 and missing indexes.Happy-path and error-path tests for every resource.
W10Text-generation endpointService that calls OpenAI or Gemini. Timeouts, retries, redaction of secrets in logs.One generation flow end-to-end from HTTP to stored result.
W11Prompt iterationSystem vs user prompts, few-shot, constraints, refusal handling. A/B two prompt versions.Prompt changelog with 10 example inputs and judged outputs.
W12Structured outputsJSON schema / response_format. Validate with Pydantic. Store both raw and parsed.Invalid JSON path: retry once, then save failure status — never crash the API.

How to implement this module

  • Prompts live in versioned files or a prompt_versions table — not hardcoded only in a route.
  • Always store model name, temperature, token usage, latency_ms, and prompt_version_id.
  • Keep a golden set of 15 inputs. Re-run after every prompt change.
  • Do not block the HTTP worker on long generations if jobs exceed ~15s — add a job status field now even if sync is still OK.

Gate: Public URL + Swagger + demo script of 3 user flows.

Deliverable: Deployed GenAI MVP with docs, logs, and a written provider comparison.

Day shape: Morning: UI or deploy friction. Afternoon: evaluation runs. Friday: record a 3-minute demo video.

Week-by-week

WeekThemeTeach / practiceYou ship

  • Never deploy API keys in the frontend. Server-side only.
  • Swagger must match real request/response examples from production.
  • Hyperparameter work is evidence for the final pitch: screenshots and CSVs in /evals.

Module 5 — Advanced 7: Optional v2 features and AI productivity

Weeks 17–20 · 200 UE · Theme: hardening + agentic + ops

Exit outcome: Add JWT auth, tests, embeddings, tracing, a small agentic flow, and an n8n automation that saves you time.

Stack: JWT, pytest + httpx, OpenTelemetry or Langfuse, embeddings API, n8n.

Gate: Authenticated API, CI tests green, one traced agent path, one live n8n workflow.

Deliverable: v1.5 product: secure, tested, observable, with one agent and one automation.

Day shape: Morning: hardening (auth/tests). Afternoon: agent or n8n. Do not start RAG until Module 6 unless the embeddings lab is done.

Week-by-week

WeekThemeTeach / practiceYou ship
W17Agents and agentic flowsTool calling, planner/executor, loop limits, human approval for irreversible actions.One agent that uses 2–3 tools (DB lookup, web/search stub, generator) with a max-step cap.
W18JWT + testingRegister/login, protected routes, password hashing. Unit tests for services, API tests for routes.CI (GitHub Actions) runs pytest on every push.
W19Embeddings + tracingText preprocessing, embedding a few records, cosine similarity prototype. Trace LLM spans.Langfuse or equivalent: you can click one user request and see prompts and tokens.
W20n8n productivityAutomate something real: daily eval digest, error webhook, or content intake into your app.Exported n8n workflow JSON in the repo plus a short SOP.

How to implement this module

  • An agent without eval is a demo toy — log tool calls and final answer quality on 10 scenarios.
  • JWT in httpOnly cookies or Authorization header; document both for Swagger.
  • n8n is for leverage (notifications, ETL, scheduling), not a replacement for the core app.
  • Embeddings this week are a stepping stone to RAG, not a full vector database yet.

Module 6 — Advanced 8: v2 features and portfolio finalization

Weeks 21–24 · 200 UE · Theme: RAG, local models, eval, pitch

Exit outcome: Ship a working RAG path, optional local model, evaluation report, and a career-ready pitch with live demo.

Stack: Chroma/pgvector, chunking pipeline, Ollama optional, eval harness, slide deck.

Gate: Live demo of RAG + generation; 8-minute pitch; public repo and deployed app.

Deliverable: Fully functional GenAI app, eval evidence, presentation, and application-phase materials.

Day shape: Morning: RAG/eval engineering. Afternoon: product polish or career artifacts. Last three days: rehearsal only.

Week-by-week

WeekThemeTeach / practiceYou ship
W21Local models + RAG ingestOllama or similar for a small local client. Document loaders, chunk sizes, overlap, metadata.Ingest 10–50 domain documents into a vector store with source citations.
W22RAG query pathRetrieve k chunks, ground the prompt, return citations. Handle empty retrieval.UI shows answer + sources. Toggle RAG on/off for comparison.
W23Fine-tune awareness + evalWhen fine-tuning is vs is not worth it. Run LLM-as-judge or rubric eval on RAG and non-RAG.Eval report: faithfulness, relevance, latency, cost. Fine-tune only if data and time exist.
W24Finalize + present + careerPolish UX, README, architecture, limitations. Pitch + live demo. CV/LinkedIn/applications.Final tag v1.0, recorded demo, one-pager, and application tracker started.

How to implement this module

  • RAG quality comes from chunking and metadata more than from the fancy vector DB brand.
  • Fine-tuning is optional and easy to overrun — default to RAG + better prompts unless the school requires a tune job.
  • Pitch structure: problem, user, demo, architecture, eval numbers, ethics, next 90 days.
  • Career week is part of the module: 10 targeted applications beat a perfect extra feature.

4. Final presentation checklist (week 24)

  • Problem, user, and why an LLM is the right tool (90 seconds).
  • Live demo: CRUD, generate, RAG citation, auth-protected path.
  • Architecture slide: request path, models, vector store, eval.
  • Numbers: latency, approx. cost/request, eval rubric scores.
  • Ethics: data, failure modes, human review.
  • Limits and 90-day roadmap. Repo + deployed URL on the last slide.

5. What not to do

  • Do not start a full RAG pipeline before Module 6.
  • Do not put API keys in the frontend.
  • Do not change the product domain after week 4.
  • Do not skip eval tables — they are evidence for the pitch.
